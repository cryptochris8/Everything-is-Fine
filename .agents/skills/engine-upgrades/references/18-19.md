# 18 → 19

## 1. `Object3D.setHidden` removed

`THREE.Object3D.setHidden` is removed.

Hide this object and its children:

```ts
// Before (18)
node.setHidden(flag, true);

// After (19)
node.visible = !flag;
```

Hide this object only (second argument omitted or `false`):

```ts
// Before (18)
node.setHidden(flag);

// After (19)
node.selfHidden = flag;
```

## 2. `NpcMovementOptions.movementSpeed` and `turnSpeed` removed

`NpcMovementNode` no longer accepts `movementSpeed` or `turnSpeed`. Those options were aliases that overrode `maxSpeed` and `lookRightSpeed` during `initialize`. Pass the inherited fields directly. There is no deprecated shim.

If you omit them, an NPC defaults to `maxSpeed` 5 m/s (§25) and `lookRightSpeed` 10 rad/s.

```ts
// Before (18)
ENGINE.NpcMovementNode.create({
  movementSpeed: 8,
  turnSpeed: 2,
});

// After (19)
ENGINE.NpcMovementNode.create({
  maxSpeed: 8,
  lookRightSpeed: 2,
});
```

## 4. Deprecated `*Component` aliases removed — use the `*Node` classes

Version 14 renamed every `*Component` class to `*Node` and kept the old names as deprecated aliases. In 19 those aliases are gone. Each alias had three forms: a value (`ENGINE.MeshComponent.create(...)`, `instanceof`), a type (`ENGINE.MeshComponent`), and an options type (`ENGINE.MeshComponentOptions`). All three are removed. The project lint preset already reports them through `@typescript-eslint/no-deprecated`. Use the `*Node` class and `*NodeOptions` type.

For these names, replace the `Component` suffix with `Node` (and `ComponentOptions` with `NodeOptions`):

`AerialMovement`, `AirplaneMovement`, `AmbientLight`, `AnimationStateMachine`, `BaseInstancedMesh`, `BasePawnMovement`, `BaseWeapon`, `BehaviorTree`, `Billboard`, `CSG`, `CSGCube`, `CSGCylinder`, `CSGSphere`, `CanvasUI`, `CharacterMovement`, `CharacterStats`, `CollisionShape`, `DirectionalCharacterMovement`, `DirectionalLight`, `Door`, `Fog`, `Follow`, `HealthPickup`, `HemisphereLight`, `InstancedMesh`, `InstancedModelMesh`, `InstantHitWeapon`, `Interaction`, `Light`, `LightProbeGrid`, `Mesh`, `ModelMesh`, `Mover`, `NpcMovement`, `PathMovement`, `Pickup`, `PickupSpawner`, `PointLight`, `Primitive`, `ProjectileWeapon`, `ProximityInteractable`, `RectAreaLight`, `ResetPosition`, `Scene`, `SceneEnvironment`, `Shotgun`, `Sky`, `Sound`, `SpectatorMovement`, `SplineMesh`, `SpotLight`, `SpringArm`, `Switch`, `TerrainMesh`, `Text`, `TopDownMovement`, `TriggerZone`, `TweenMovement`, `UI3D`, `VFX`, `VRBase`, `VRGrab`, `VRGrabbable`, `VRInteract`, `VRInteractable`, `VRSnapTurn`, `VRTeleport`, `VehicleMovement`, `ViewTargetCamera`, `VoxelMesh`

## 6. Deprecated forwarding methods removed

Each method below only called its replacement. Rename each call, override, or property access. A subclass that overrides a removed `protected` method (for example `setupVisualComponent`) must override the replacement instead, or the engine no longer calls it.

| Class | Removed | Use instead |
| --- | --- | --- |
| `World` | `addActor(node)`, `addActors(...nodes)` | `add(...nodes)` |
| `World` | `removeActor(node)`, `removeActors(...nodes)` | `node.destroy()` |
| `SceneNode` | `addComponent(node)`, `addComponents(...nodes)` | `add(...nodes)` |
| `SceneNode` | `waitForComponentsToLoad()` | `waitForNodesToLoad()` |
| `SceneNode` | `isRootComponent()` | `isRoot` |
| `Object3D` | `getActor()` | `getRoot()` |
| `Object3D` | `getComponent(type)` | `getNode(type)` |
| `Object3D` | `getComponents(type)` | `getNodes(type)` |
| `AIController` | `moveToActor(...)` | `moveToTarget(...)` |
| `AIController` | `getFollowedActor()` | `getFollowedTarget()` |
| `MovementPawn` | `movementComponent` | `movementNode` |
| `CharacterPawn` | `visualComponent`, `animationComponent` | `visualNode`, `animationNode` |
| `MoverCharacterPawn` | The whole class | Removed. See section 14. |
| `GameplayPawn`, `DefaultCharacterPawn` | `getInteractionComponent()` | `getInteractionNode()` |
| `ModelMeshNode` | `getModel()` | Use the `ModelMeshNode` instance directly. |
| Physics engine | `hasComponent`, `addComponent`, `removeComponent`, `setComponentCollisionIgnore`, `getComponentState` | `hasNode`, `addNode`, `removeNode`, `setNodeCollisionIgnore`, `getNodeState` |

`getActor()` returned the root only when it was an `Actor`. `getRoot()` returns the nearest ancestor with `isRoot` set, so check for a specific class yourself if you need one.

```ts
// Before (18)
world.addActors(a, b);
world.removeActor(a);
const owner = mesh.getActor();
const lights = owner?.getComponents(ENGINE.LightNode) ?? [];
await root.waitForComponentsToLoad();
pawn.movementComponent = movement;

// After (19)
world.add(a, b);
a.destroy();
const owner = mesh.getRoot();
const lights = owner?.getNodes(ENGINE.LightNode) ?? [];
await root.waitForNodesToLoad();
pawn.movementNode = movement;
```

## 10. Old class names in saved data no longer resolve

Earlier versions registered redirects so saved scenes, prefabs, and materials that used an old class name still loaded. In 19 those redirects are gone. An object whose `$bc` (or `$class`) holds an old name is not created. The loader logs `Class not found for name ...` and builds a plain object in its place.

Open each saved scene, prefab, and material asset in your project and rename the class names in the JSON. Search for the old name, replace it with the new one.

| Old name in saved data | New name |
| --- | --- |
| `ENGINE.<Name>Component` for every class in the section 4 list | `ENGINE.<Name>Node` |
| `ENGINE.GLTFMeshComponent`, `ENGINE.ModelMeshComponent` | `ENGINE.ModelMeshNode` |
| `ENGINE.InstancedGltfMeshComponent`, `ENGINE.InstancedModelMeshComponent` | `ENGINE.InstancedModelMeshNode` |
| `ENGINE.SkyboxComponent`, `ENGINE.SceneEnvironmentComponent` | `ENGINE.SceneEnvironmentNode` |
| `ENGINE.GLTMeshActor` (misspelled), `ENGINE.GLTFMeshActor` | One `ENGINE.ModelMeshNode` with `isRoot: true`. `ModelMeshActor` is removed too (section 11). |
| `ENGINE.GLTFMeshSocket` | `ENGINE.MeshSocket` |
| `ENGINE.VRActor` | `ENGINE.VRNode` |
| `ENGINE.InfoActor` | `ENGINE.InfoNode` |
| `ENGINE.FollowActorAction` | `ENGINE.FollowTargetAction` |
| `ENGINE.BasicNodeMaterialAsset`, `LambertNodeMaterialAsset`, `PhongNodeMaterialAsset`, `StandardNodeMaterialAsset`, `PhysicalNodeMaterialAsset`, `ToonNodeMaterialAsset`, `MatcapNodeMaterialAsset`, `NormalNodeMaterialAsset` | The same name with a `Mesh` prefix, for example `ENGINE.MeshBasicNodeMaterialAsset` |

Two redirects stay: `THREE.Source` to `THREE.TextureSource`, and `GAME.DynamicUVNodeMaterialAsset` to `ENGINE.DynamicUVNodeMaterialAsset` (used only when your game does not register its own class with that name).

## 11. `ModelMeshActor` removed

`ModelMeshActor`, `ModelMeshActorOptions`, and the aliases `GLTFMeshActor`, `GLTFMeshActorOptions` are removed. The class was a shell root with one `ModelMeshNode` child named `Mesh`. Use a `ModelMeshNode` that is its own root.

| Removed | Use instead |
| --- | --- |
| `ModelMeshActor.create(options)` | `ModelMeshNode.create({ ...options, isRoot: true })` |
| `getMeshNode()`, `getMeshComponent()` | The node itself. |
| `waitForLoad()` | `ModelMeshNode.waitForLoad()` |

Saved data with `ENGINE.ModelMeshActor` (or `ENGINE.GLTFMeshActor`) no longer creates an object. Replace the shell and its `Mesh` child with one `ModelMeshNode` in the scene or prefab.

```ts
// Before (18)
const rock = ENGINE.ModelMeshActor.create({ modelUrl, physicsOptions });
await rock.waitForLoad();

// After (19)
const rock = ENGINE.ModelMeshNode.create({ modelUrl, physicsOptions, isRoot: true });
await rock.waitForLoad();
```

## 12. `Actor` removed

`ENGINE.Actor`, `ActorOptions`, and the `rootComponent` and `sceneComponents` options are removed. `Actor` was a `PrimitiveNode` that was always its own root. Use `PrimitiveNode` (or `SceneNode`, or your own subclass) with `isRoot`.

| Removed | Use instead |
| --- | --- |
| `class X extends ENGINE.Actor` | `class X extends ENGINE.PrimitiveNode`. Set `this.isRoot = true` in the constructor. |
| `Actor.create(options)` | `PrimitiveNode.create({ ...options, isRoot: true })` |
| `rootComponent: body` option | Add `body` to `children`, or call `this.add(body)` in `initialize`. |
| `sceneComponents: [...]` option | `children: [...]` |
| `actor.rootComponent` | The node itself, or `getRoot()` |
| `Actor.netLocalRole`, `netRemoteRole` | `node.getReplicationInfo()?.netLocalRole`, `?.netRemoteRole` |
| `Actor.setAutonomousProxy(flag)` | `node.getReplicationInfo()?.setAutonomousProxy(flag)` |
| `Actor.replicateTransform`, `netTransform`, `onRepNetTransform` | Declare replicated position and rotation properties on your class and apply them in an `onRep*` callback. Or use `MovementPawn` or `CharacterPawn`, which replicate movement. |
| `Actor.isPhysicsEnabled()` that also checked children | `PrimitiveNode.isPhysicsEnabled()` checks only the node itself. Check `getNodes(PrimitiveNode)` yourself if you need the children. |
| `collapseSingleChildShells(world, classes)` | None. It removed `Actor` and `ModelMeshActor` wrappers from old scenes. |

`hasAuthority()` works on every `SceneNode` and is `true` when the node is not replicated.

Saved data with `$bc: "ENGINE.Actor"` no longer creates an object. Replace the class name with `ENGINE.PrimitiveNode` in your scenes and prefabs. Also convert any `rootComponent` or `sceneComponents` keys in saved data to `children`. The editor action "Collapse Single-Child Shells" and the "Empty" place tool changed too: Empty now places a `PrimitiveNode` root.

```ts
// Before (18)
@ENGINE.GameClass()
class Crate extends ENGINE.Actor {
  public override initialize(options?: ENGINE.ActorOptions): void {
    super.initialize({ ...options, rootComponent: ENGINE.MeshNode.create({ geometry }) });
  }
}

// After (19)
@ENGINE.GameClass()
class Crate extends ENGINE.PrimitiveNode {
  constructor() {
    super();
    this.isRoot = true;
  }

  public override initialize(options?: ENGINE.PrimitiveNodeOptions): void {
    super.initialize(options);
    this.add(ENGINE.MeshNode.create({ geometry }));
  }
}
```

## 13. Legacy saved-data migration removed

The loader no longer rewrites scenes and prefabs saved by engine 13 or earlier. The `$version` gate and the `migrateFrom` property option still work, but the legacy passes behind them are gone. Open and re-save these files in an older engine first, or convert them by hand.

| Removed | Use instead |
| --- | --- |
| `rootComponent` key on a node or `ENGINE.Prefab` | Move the body under `children`. The loader ignores the key. |
| `sceneComponents` and `actors` keys on `ENGINE.World` and `ENGINE.Prefab` | `children` on the world, `rootNode` on the prefab. The loader ignores these keys. |
| Bare Actor `.prefab.json` (root is not `ENGINE.Prefab`) | Wrap it by hand: `{ "$bc": "ENGINE.Prefab", "rootNode": <old root> }`. |
| `$prefab: { $path }` stamp and `prefabNodeId` | `$base: { $path }` with `prefabPath`, and `prefabId`. |
| `$uuid` key on `ENGINE.World` | `uuid`. A world saved with `$uuid` gets a new id on load. |
| `settings.gameMode` object (`{ "$bc": "X" }` or `{ "$base": { "$class": "X" } }`) on `ENGINE.World` | `settings.gameModeClass: "X"`. `WorldSerializer.extractGameMode` and `World` no longer read the old object. |
| `settings` at the top level of the document, outside `$root` | `$root.settings`. |
| `convertPrefabDocument`, `prefabPathMap`, `rewritePrefabStamps` options of `migrateSerializedData` and `prepareSerializedDataForLoad` | Call them with the document only. |
| `@property({ ignoreNameWhenMatchingExisting })` | None. Name matching always applies. |
| `SceneNode.applyLegacyRootComponent` override point | None. |
| `scripts/migrate-engine-assets.ts` and `scripts/migrate-sdk-template-prefabs.ts` (engine repo only) | None. |

Still available: `prepareSerializedDataForLoad(data)`, `migrateSerializedData(data)`, `serializedDataNeedsMigration(data)`, and `@property({ migrateFrom: 'oldName' })`. The gate now clones an outdated document and stamps the current `$version`. Add your own rewrite passes to it only if you fork the engine.

## 14. Mover removed

The Mover movement stack is removed. It was unsupported since GSS shipped. There is no deprecated shim. Removed exports:

- Node, pawn, and controller: `MoverNode`, `MoverNodeOptions`, `MoverCharacterPawn`, `MoverPlayerController`.
- Modes: `WalkingMode`, `FallingMode`, `FlyingMode`, `AirplaneMode`, `AerialMode`, `TopDownMode`, `VehicleMode`, their `*Options` types and `*_TAG` constants.
- Framework: `IMovementMode`, `IMoverTransition`, `IMoverBackend`, `StandaloneMoverBackend`, `IMovementInputProducer`, `LayeredMove`, `MovementModifier`, `MovementModifierHandle`, `MoveMixMode`.
- Data types: `MovementInputCmd`, `MovementSyncState`, `MovementAuxState`, `MovementDataCollection`, `ProposedMove`, `MoverTimeStep`, `MoverTickStartData`, `MoverTickEndData`, `SimulationTickParams`, and the `InputCmdKeys` helpers.

`AIController` now drives only a `GSSNode`. It no longer implements `IMovementInputProducer` or has `produceInput(simTimeMs, cmd)`, and on a pawn without a `GSSNode` it warns and does not steer.

| Mover | Use instead |
| --- | --- |

| `TopDownMode` | `TopDownMovementNode` |
| `VehicleMode` | `VehicleMovementNode` |
| `AerialMode` | `AerialMovementNode` |

Saved data with `ENGINE.MoverCharacterPawn` or `ENGINE.MoverNode` no longer creates an object. Replace the pawn in your scenes and prefabs.

```ts
// Before (18)
class MyPawn extends ENGINE.MoverCharacterPawn {
  protected override createMoverNode(): ENGINE.MoverNode {
    const mover = ENGINE.MoverNode.create({ name: 'MoverNode' });

// After (19)
class MyPawn extends ENGINE.GSSCharacterPawn {
  protected override createGSSNode(): ENGINE.GSSNode {
    const sim = super.createGSSNode();
    sim.addMovementMode(new ENGINE.GSSWalkingMode({ maxSpeed: 8 }));
    return sim;
  }
}
```

## 15. `performHitTest` deprecated

`IPhysicsEngine.performHitTest` still runs, but it is deprecated. Use `raycast` for the nearest hit and `raycastAll` for every hit, ordered nearest first.

`raycast` and `raycastAll` normalize `direction`. `performHitTest` does not, so a non-unit direction scales `maxDistance` and the spacing of its hits. Pass the world-space distance the ray should travel.

A `PhysicsQueryHit` has `hitLocation`, `hitNormal`, `hitNode`, and `distance`. It has no `hitRoot`; use `hit.hitNode?.getRoot() ?? null`. There is no `stopOnFirstHit` flag. Triggers stay excluded unless `includeTriggers` is set.

`InstantHitWeaponNode.processHit` and `applyDamage` now take `PhysicsQueryHit` instead of `HitTestResult`. `HitTestOptions` and `HitTestResult` are deprecated with `performHitTest`.

```ts
// Before (18) — still compiles, deprecated
const hits = physics.performHitTest({
  origin,
  direction,
  maxDistance: 100,
  stopOnFirstHit: true,
});
const root = hits[0]?.hitRoot ?? null;

// After (19)
const hit = physics.raycast({
  origin,
  direction,
  maxDistance: 100,
});
const root = hit?.hitNode?.getRoot() ?? null;
```

Every hit along the ray:

```ts
// Before (18) — still compiles, deprecated
const hits = physics.performHitTest({
  origin,
  direction,
  maxDistance: 100,
  stopOnFirstHit: false,
});

// After (19)
const hits = physics.raycastAll({
  origin,
  direction,
  maxDistance: 100,
});
```

## 16. Matchmaking HTTP configuration moved to the host

`MatchmakingClient`, `MatchmakingClientOptions`, `DEFAULT_MATCHMAKING_BASE_URL`, `NONPROD_MATCHMAKING_BASE_URL`, `DEV_MATCHMAKING_BASE_URL`, and `resolveDefaultMatchmakingBaseUrl` are removed. The engine no longer chooses an API URL, sends credentials, or creates an HTTP client.

`MatchmakingConfig.baseUrl` and `MatchmakingConfig.gameId` are also removed. `MatchmakingConfig.client` is now required and implements `IMatchmakingClient`. The host supplies this client together with the published game id and matchmaking player id. Game code must pass the host options through unchanged. If no client is supplied, the first use of `findMatch`, `acceptMatch`, or `matchmaking` throws `MatchmakingError`.

```ts
// Before (18)
return new MyGame(container, {
  ...options,
  matchmaking: {
    baseUrl: ENGINE.DEFAULT_MATCHMAKING_BASE_URL,
    gameId: options?.gameId,
  },
});

// After (19)
return new MyGame(container, {
  ...options, // includes gameId and matchmaking.client from the host
});
```

Do not create an `IMatchmakingClient` in game code or override the host's `matchmaking` option. A custom host or test harness must implement `IMatchmakingClient` and inject it:

```ts
const game = new MyGame(container, {
  gameId,
  matchmaking: {
    client: hostMatchmakingClient,
  },
});
```

The controller does not take a player id. The host client authenticates each request, and the matchmaking API takes the player from that credential.

## 17. `FollowNode.positionDamping` is scaled by delta time

`positionDamping` is now the fraction of the gap closed per 1/60 s, so the chase lag is the same at any frame rate. At 60 fps a value behaves as before. Delete any subclass that converted the damping per tick itself (the camera skill's old `SteadyFollowNode`); kept, it converts twice and snaps harder below 60 fps.

```ts
// Before (18)
SteadyFollowNode.create({ target: this, positionDamping: 0.02 }); // damping60 = 0.02

// After (19)
ENGINE.FollowNode.create({ target: this, positionDamping: 0.02 });
```

## 18. Behavior-tree timers use game time

The built-in waits, cooldowns and time limits (`WaitAction`, `ShootAction`, `MeleeAttackAction`, `WanderAction`, the aerial actions, `TimeLimitCondition`, `HasLastKnownPositionCondition`) now read `blackboard.getGameTime()`, the world's game time, instead of `Date.now()`. Pause stops them and slow motion slows them.

Game code that writes a start time for `TimeLimitCondition` (`startTimeKey`) or a `<key>_Timestamp` for `HasLastKnownPositionCondition` must write game-time seconds:

```ts
// Before (18)
blackboard.setValue('TimeLimitStartTime', Date.now() / 1000);

// After (19)
blackboard.setValue('TimeLimitStartTime', blackboard.getGameTime());
```

## 19. An interrupted behavior-tree action runs `onExit`

When a failed attached condition cuts off a `Running` node, the node is now reset, and a reset of an action mid-run calls its `onExit` with `Failure`. Before, neither ran `onExit`, so a Follow or MoveTo cut off by its condition kept moving the NPC. Drop workarounds that stopped the movement node themselves (for example a `GatedFollowTargetAction` subclass) and use `FollowTargetAction`. Cleanup that a custom action repeated in `onReset` now belongs in `onExit` only.

## 20. `createTween` tweens use the manager's clock and always untrack

A tween from `world.tweenManager.createTween` now defaults `start()`, `pause()` and `resume()` to `getCurrentTime()` instead of the wall clock, and a custom `.onComplete` or `.onStop` runs after the manager's auto-remove instead of replacing it. Keep passing `getCurrentTime()` to `.start()` (the lint rule requires it). Drop `removeTween(tween)` calls made inside those callbacks; they are no longer needed.

## 21. Navmesh agent sizes in the scene settings are metres

`NavigationSettings` (the NavMesh dialog, MCP `setSettings`, `<scene>.navmsettings.json`) now converts Agent Radius, Agent Height and Max Step Height from metres to Recast voxels before a bake. Before, the metre values reached Recast as voxel counts: the default 0.5 m radius eroded nothing and the step height was 0. Re-bake each scene. Corridors narrower than twice the agent radius now drop out of the navmesh, and a step higher than Max Step Height splits it. A scene whose settings hold voxel counts typed in as a workaround (a radius of 3 for 0.6 m) must go back to metres. Options set on the navigation server in code stay voxel counts.

## 22. GSS modes mix effect movement proposals

`IGSSMovementMode.generateMove` now receives the active effects' proposals:

```ts
generateMove(ctx: GSSMovementContext, proposals: readonly GSSProposedMove[]): GSSDesiredMove
```

`GSSDesiredMove` is only `{ velocity }`. There is no `verticalMix`. The node passes the proposals through and does not mix them. `mixProposedMoves(seed, proposals)` is the per-axis mixer: `Override` replaces that axis, `Additive` adds to it, `Ignore` leaves it. Walking and falling put the current vertical speed on the seed, or `jumpSpeed` when a jump is allowed, then mix. `tick` uses the resolved `velocity.y` and then adds gravity. `GSSIdleMode` mixes proposals only when `applyEffectMoves` is true.

A custom mode still declared as `generateMove(ctx)` does not compile. Take the proposals argument. Ignoring it means effects no longer move that mode. Delete any read of `move.verticalMix`. Do not apply `velocity.y` a second time in `tick`: it is already the mixed vertical speed, and adding it again double-counts an Additive launch. A subclass that copied `move.velocity.y` onto its own vertical speed to force launches should drop that copy.

## 23. A GSS pawn's camera keeps its initial pitch

`GSSPlayerController` now starts the look pitch at a `GSSCharacterPawn`'s camera pitch when it possesses it. Before, the pitch started at 0, so `updateCamera` levelled the camera on the first frame and the angle from `getInitialCameraPositions` was lost. The default third-person camera now starts tilted down at the pawn. Remove an `updateCamera` or `setupCamera` override written only to keep that angle.

## 24. The default jump reaches about 1.5 m

`CHARACTER_JUMP_SPEED` is now 12 m/s (was 20), the default `jumpSpeed` of `CharacterMovementNode`, `GSSWalkingMode` and `GSSFallingMode`. The apex drops from about 4.1 m to 1.5 m and the airtime from 0.82 s to 0.49 s. A pawn that never set `jumpSpeed` now jumps lower: re-check gaps and ledges it had to clear, or pass `jumpSpeed: 20` to keep the old jump.

## 25. `NpcMovementNode` walks at the player's speed by default

When `maxSpeed` is omitted, `NpcMovementNode` now uses the player default, `CHARACTER_MAX_SPEED` (5 m/s), instead of 20 m/s. NPCs that relied on the default chase four times slower. Pass `maxSpeed` for a faster enemy.

## 26. Projectiles live 10 s by default

`Projectile.projectileLifespan` now defaults to 10 s (was no limit), so a miss with no `range` or lifespan no longer flies forever. A shot that must travel longer sets its own `projectileLifespan`; 0 still means no time limit.

## 27. The sky dome's 10000 scale is on the sky mesh

`SkyNode` now scales its internal sky mesh by the hidden `skyMeshScale` property (10000) and leaves the node at scale 1. Before, the node itself was at 10000, so a `SkyNode` set to scale 1 turned the scene black. Saved skies still look the same: one saved without `skyMeshScale` comes from an older engine, and loading it divides its node scale by 10000.

Code that creates a `SkyNode` with `scale: 10000`, or sets that scale, now makes the dome 10000 times bigger. Remove the scale.

## 28. `AnimationClipCache` is keyed by source and target rig

The cache was keyed by clip name alone, so two characters on different rigs that both loaded a clip called `Idle` overwrote each other, and the loser animated on the wrong skeleton. Entries are now keyed by `(targetProfile, targetRig, sourceUrl, clipName)`.

Nothing was removed. The name-based overloads still exist and are marked `@deprecated`. A project that never calls this class needs no change. `externalAnimationSources` in the animation config fills the cache for you, and that path needs no change either.

```ts
// Before (18) — still compiles, deprecated
ENGINE.AnimationClipCache.instance.addClip(clip);
ENGINE.AnimationClipCache.instance.addClips(clips);
const idle = ENGINE.AnimationClipCache.instance.getClip('Idle');

// After (19)
const key = {
  targetProfile: 'Manny',                                  // SkeletonProfile.name the clip is retargeted to
  sourceUrl: '@project/assets/animation/locomotion.glb',   // GLB the clip came from
  clipName: 'Idle',
};
ENGINE.AnimationClipCache.instance.addClip(key, clip);
const idle = ENGINE.AnimationClipCache.instance.getClip(key);
```

- `hasClip` and `removeClip` take the same key. Use `ENGINE.ANIMATION_CLIP_CACHE_NO_PROFILE` as `targetProfile` for clips that were not retargeted.
- `targetRig` is optional: `ENGINE.getAnimationRigKey(skeleton)` of the skeleton a clip was retargeted onto. Omit it for clips that were not retargeted. An entry without it only matches lookups without it.
- `addClips` has no keyed form. Call `addClip` once per clip.
- `getClip('Idle')` by bare name still reaches clips the animation config loaded, but once two sources or rigs provide that name, which one it returns is arbitrary.
- `removeClip('Idle')` drops only entries added by name. It does not reach clips the loader cached for other rigs.

Run `pnpm lint`. The project's ESLint config sets `@typescript-eslint/no-deprecated` to `error`, so it reports every call site to migrate.

When every clip of a source is already cached for a character's rig, the next character on that rig reuses those clips instead of retargeting again. `targetRig` is what tells rigs apart: two characters with the same profile but different bone lengths or bind pose, such as a tall and a short Mixamo character, each get their own retarget.

## 29. A state machine plays its own clips, plus clips handed to it

`AnimationStateMachineNode` used to import every clip in the process-wide cache into its mixer, so a clip that unrelated code loaded became playable through `play()` or `blendTo()`. It now creates actions for its own clips and for the clips its states, blends, and one-shots name. When a name exists in more than one place, the first match wins:

1. A clip source mapped through `bindModelMesh(mesh, { clipSources })`, as avatar looks do.
2. The sources in its own `externalAnimationSources`. When several carry the same name, the first one declared wins and the engine warns once.
3. Clips given to `registerClips`.
4. The model's own clips.
5. Clips added to `AnimationClipCache` by name, only for names the config uses. The engine warns once per process when it falls back to one.

A clip the config does not name must now be registered on the state machine that plays it:

```ts
// Before (18) — the clip became playable on every state machine
ENGINE.AnimationClipCache.instance.addClip(happyIdle);
animationNode.blendTo('HappyIdle');

// After (19)
animationNode.registerClips([happyIdle]);
animationNode.blendTo('HappyIdle');
```

`registerClips` may run before the config finishes loading, and the clips survive a rebind to another model. `blendTo()` with a clip that has no action now warns.

## 30. `PlayerInfo` replicates `avatarId`

`PlayerInfo` has a new replicated string, `avatarId`, declared between `playerName` and `isReady`. It changes the replicated layout of `PlayerInfo` and every subclass, so clients and dedicated servers must run the same engine build. A subclass that declares its own `avatarId` field must rename it.

The engine fills it from the join handshake when the client sends an id the avatar service already knows. Otherwise it stays `''`. An avatar pawn reads it when a player possesses it.

`JoinParams` is still `Record<string, string>`. The client asks for a look with `joinParams.avatarId`. A key the client did not send is missing at runtime, so read optional keys with a fallback, for example `joinParams.team ?? ''`.

`InactivePlayerSnapshot` has a matching optional `avatarId`, so a player who rejoins (§35) keeps their look. A subclass that overrides `captureInactiveState` without calling `super` must copy `avatarId` itself.

## 31. Standalone play spawns a `PlayerInfo`

In standalone, `GameMode.onPlayerJoined` now spawns a `PlayerInfo` and links it to the controller before `handleNewPlayer`, unless the controller already has one. Before, a standalone controller had no `PlayerInfo`.

- `playerInfoFactory` now also runs in standalone, and `applyJoinParamsToPlayerInfo` runs on the result.
- `controller.getPlayerInfo()` is no longer `null` in standalone. Code that used `null` to detect standalone play must check `ENGINE.NetRuntime.isStandalone()` instead.
- A game that created its own `PlayerInfo` in `handleNewPlayer` now ends up with two. Create it through `playerInfoFactory` instead, or check `controller.getPlayerInfo()` first.

## 32. `CharacterPawn` animation parameters come from an animation driver

`CharacterPawn.getAnimationParameters()` used to compute the locomotion parameters itself. It now returns what the driver registered for `getAvatarAnimationDriverId()` produces, which is `'character-locomotion@1'` for every stock character pawn. The parameters are the same: `isRunning`, `isJumping`, `forward`, `back`, `left`, and `right`.

- A subclass that overrides `getAnimationParameters()` keeps working unchanged.
- Driver ids are versioned as `name@version`. `ENGINE.registerAvatarAnimationDriver` throws for an id without a version and for an id that is already registered, so the stock `'character-locomotion@1'` cannot be replaced. Register custom drivers under your own id, such as `'my-game-locomotion@1'`, and return that id from your pawn's `getAvatarAnimationDriverId()`.
- `ENGINE.clearAvatarAnimationDrivers()` leaves every `CharacterPawn` without animation parameters. Call it only in tests.

## 33. Avatar looks replicate on the pawn

The server writes each pawn's look onto `AvatarAppearanceNode.avatarId`. Clients compose when that property replicates (`onRepAvatarId`), on the owning client and on everyone else. `PlayerInfo.avatarId` is still replicated, for scoreboards and rejoin, and no longer applies the mesh.

Removed:

- `NetWorld.onEntityEstablished`
- `PlayerInfo.onRepAvatarId`
- `GameMode.onPlayerAvatarIdReplicated`, `applyReplicatedAvatar`, `findAvatarPawnForClient` and `findPlayerInfoForClient`

Change a player's look with `ENGINE.assignPlayerAvatar(controller, avatarId)`. It updates `PlayerInfo` and the current pawn, and the next respawn reuses it. The pawn opts in with `useAvatarAppearance` (or by spawning `AvatarCharacterPawn`); `GameMode` does not choose the pawn or dress it.

`AvatarApplyResult` (`'applied' | 'skipped' | 'superseded' | 'failed'`) is still `ENGINE.AvatarApplyResult`. The type moved out of `GameMode.ts` into the avatar module; games that name it keep compiling.

An empty id is never replicated. A player with no look gets the pawn's `defaultAvatarId`, or `ENGINE.AVATAR_ID_SERVICE_DEFAULT` (`'@default'`), which means the avatar service's default. Do not send `'@default'` in `JoinParams.avatarId`; the server rejects it. `GSSCharacterPawn` declares `character-locomotion@1`, so the same looks animate on the gameplay-sim pawn.

## 34. Player identity comes from admission, not `joinParams`

The client no longer chooses its own identity. A dedicated server started with `launcher-server --host-module <path>` asks that platform host to admit each client. The host checks the join token and returns the player's `playerId`, plus an optional profile (`displayName`, `accountType`). Without `--host-module`, every client is admitted as `client-<clientId>` with no profile.

Removed:

- `PlayerInfo.identityToken`
- `InactivePlayerSnapshot.identityToken`
- The engine no longer reads `joinParams.identityToken`

Added:

- `PlayerInfo.playerId`: the verified id. It is replicated to every client.
- `InactivePlayerSnapshot.playerId`
- An optional third argument on `GameMode.canPlayerJoin` and `GameMode.handleServerPlayerJoin`: `identity?: ServerPlayerIdentity` (`{ playerId, profile? }`)

The engine writes `playerId`. Game code must not set it, and must stop storing a token on the client and sending it back:

```ts
// Before (18)
await gameLoop.connectToServer(url, { identityToken: savedToken });
playerInfo.identityToken = token;

// After (19)
await gameLoop.connectToServer(url);
// The host returns the same playerId on the next connect. Nothing to store.
```

Read identity on the server from the new argument, never from `joinParams`:

```ts
// After (19)
override canPlayerJoin(
  clientId: ENGINE.ClientId,
  joinParams: ENGINE.JoinParams,
  identity?: ENGINE.ServerPlayerIdentity,
): ENGINE.PlayerJoinResult {
  if (identity?.profile?.accountType === 'anonymous') {
    return { allowed: false, reason: 'Sign in to play ranked.' };
  }
  return { allowed: true };
}
```

An override that keeps the two-argument signature still compiles.

A subclass that overrides `captureInactiveState` without calling `super` must return `playerId` instead of `identityToken`. One that overrides `applyInactiveState` without `super` must copy `state.playerId`.

When the profile has a `displayName`, the engine uses it for `PlayerInfo.playerName`, replacing `generatePlayerName(clientId)`. It is still player-chosen text, so render it as text.

`playerId` is a new replicated field on `PlayerInfo`, like `avatarId` (§30). A subclass that declares its own `playerId` field must rename it.

## 35. Rejoin needs a platform host and has a time limit

Disconnect and rejoin still work, but keyed by the verified `playerId`:

- With a platform host, a player who reconnects with the same account gets their saved `PlayerInfo` state back (`canPlayerRejoin` runs first, as before).
- Without `--host-module` (local dev, editor Play, self-hosted servers), each connection gets a new `client-<clientId>`, so there is no rejoin.
- New `GameMode.inactivePlayerTimeoutSeconds`, default `300`. A saved state older than that is dropped, and the player joins as a new player. `0` saves nothing. Set it in the GameMode's properties, or in code on the server:

```ts
gameMode.inactivePlayerTimeoutSeconds = 120;
```

Code that reads `gameMode.inactivePlayerInfos` must allow for entries that have expired. Expired entries are removed on the next join or leave.

A leaving player's `PlayerInfo` is now always despawned through the `PlayerSpawner`, including when its state is saved. Before, a saved player was unjournaled and destroyed outside the spawner.

## 36. `sessionName` renamed to `sessionId`

| Before (18) | After (19) |
| --- | --- |
| `GameSessionDescription.sessionName` | `GameSessionDescription.sessionId` |
| `ServerGameSessionOptions.sessionName` | `ServerGameSessionOptions.sessionId` |

```ts
// Before (18)
const name = session.getDescription().sessionName;

// After (19)
const name = session.getDescription().sessionId;
```

On a dedicated server this is the platform session id, or `undefined` without a host. It is not a display name. Show your own match name from a `GameSessionInfo` subclass instead.

The client connect options (`NetClientOptions`) have two new fields, `sessionId` and `authToken`. They are sent as their own handshake fields, never in `joinParams`. Matchmaking (`findMatch`, party follow) fills both, and sends `authToken` only on WebTransport. Do not set them yourself. When the host has a session id, a client whose `sessionId` does not match is refused with the reason `wrong-session`.

## 37. `maxPlayers` removed from the session

Removed with no replacement:

- `GameSessionInfo.maxPlayers`
- `GameSessionDescription.maxPlayers`
- `IGameSession.getMaxPlayers()` and `IGameSession.setMaxPlayers()`

The engine never enforced the value. Matchmaking sizes the match, and `canPlayerJoin` is where a game enforces a cap. To show a cap in the UI, declare it on a `GameSessionInfo` subclass:

```ts
// After (19)
@ENGINE.GameClass()
export class MyGameSessionInfo extends ENGINE.GameSessionInfo {
  @ENGINE.property({ replicate: true, net: { netType: 'uint' } })
  public maxPlayers: number = 8;
}
```

Return it from an override of the GameMode's `getGameSessionInfoFactory()`.

`MatchmakingQueue.maxPlayers` and party `maxPlayers` are unchanged.

## 38. Matchmaking backfill is closed until the game opens it

New `GameMode.setAcceptingNewPlayers(open)` and `isAcceptingNewPlayers()`. Backfill starts closed. A matchmade game that wants late joiners must open it, for example in the lobby, and close it when the round starts:

```ts
// Lobby
gameMode.setAcceptingNewPlayers(true);
// Round start
gameMode.setAcceptingNewPlayers(false);
```

The flag only tells the platform whether to send more players. It never rejects a join. A player who already holds a token still reaches `canPlayerJoin`: refuse them there, or let them in and hold them for the next round. Keep a backfill window open long enough for matchmaking to find someone, up to about two minutes.

## 39. A refused join closes the connection

When the server refuses a player after the handshake (`canPlayerJoin`, `canPlayerRejoin`, admission, wrong session, no game mode, or a failed spawn), it now closes the connection with close code `4001` and the refusal reason as the close reason. Before, the socket stayed open and the client waited. The client logs the reason and does not reconnect. A reason longer than 123 UTF-8 bytes is cut to fit, so keep `canPlayerJoin` reasons short.

Code that subclasses `ServerAuthorityNetWorld`: `disconnectClient(clientId, reason)` now closes the transport this way, then runs the normal leave path. Before, it only cleaned up server state. Do not close the connection a second time.

## 40. Platform host for dedicated servers

New for platform and test-harness authors. Game code should not need it.

- `launcher-server --host-module <path>` loads a module whose default export is a `DedicatedServerHostFactory`. The launcher exits with code 1 when the module cannot be loaded or does not return a host.
- `DedicatedServerHost` gets `serverReady`, `admitPlayer` (5 s timeout, rejected on timeout or throw), `playerLeft`, `setAcceptingPlayers`, and `shuttingDown`.
- Without `--host-module`, a default host admits everyone. There is no public API to read or replace the host: games use `GameMode.setAcceptingNewPlayers` and the `identity` argument of `canPlayerJoin`.
- The host is not a security boundary. Game code runs in the same process. The platform checks tokens behind the host.
- `ConnectionDetailsJson` is now public, because `serverReady` receives it.

## 41. Adaptive quality follows the device

19 adds quality tiers (`low`, `medium`, `high`) and resolves `auto` from the device: discrete GPUs and Apple silicon on WebGPU get high; integrated GPUs, browsers without WebGPU and the classic WebGL renderer get medium; phones and weak desktops get low. Three things that already existed in 18 follow it with no code change:

| What | Low | Medium | High |
| --- | --- | --- | --- |
| `TerrainMeshNode` drawn mesh | ×0.5 of the authored segments | ×0.7 | As authored |
| GTAO (WebGPU AO) | Fewer samples, lower resolution | Fewer samples | As authored |
| Cascaded shadows (`useCsmShadows`) | One 1024 cascade, still follows the camera | At most two 1024 cascades | As authored |

Collision, height queries and saved values never change. In play, a frame-time watchdog lowers `auto` one tier after two slow windows in a row (about 12 s under 40 fps). It never goes below medium on desktop and logs each step.

To keep 18's look on every device, pin a tier before the world loads:

```ts
ENGINE.setQualityTierOverride(ENGINE.QualityTier.High); // also turns the watchdog off
```

To keep device detection but turn off the in-play step down, pass `qualityWatchdog: false` to your `BaseGameLoop` options. A single node can opt out by setting its own `quality` to `'high'`.

GTAO was also rebuilt in 19 (a depth and normal pre-pass, and a denoise pass that is on by default), so a scene with AO enabled looks different on every tier. Re-check `gtaoRadius` and `gtaoStrength` against your scene scale.

## 42. Default character clips target the new mannequin

Confirm the installed defaults in `.engine/src/const.ts` before editing. This section applies when `DEFAULT_CHARACTER_ANIMATION_CONFIG_URL` is `@engine/assets/character/config/mannequin-default.animconfig.json`. Skip it when that constant is still `@engine/assets/character/config/mannequin.animconfig.json`.

`DEFAULT_CHARACTER_MODEL_URL` is `@engine/assets/character/mannequin.glb`. `DEFAULT_CHARACTER_ANIMATION_CONFIG_URL` is `@engine/assets/character/config/mannequin-default.animconfig.json`. Those clips are authored on that skeleton. A `CharacterPawn` that inherits both `setupVisualNode` and `setupAnimationNode` still animates. Leave those methods inherited.

A subclass that overrides `setupVisualNode` and keeps a Mixamo mesh (`@engine/assets/character/mannequinG.glb`, or any other Mixamo rig) while inheriting `setupAnimationNode` plays the new clips on the old bones. The pawn stays in its bind pose and slides when it moves. Saved scenes and prefabs that already store an animation `configUrl` keep that URL. The engine does not detect the skeleton and swap configs.

Override `setupAnimationNode` and point it at the Mixamo config that still ships. Keep the existing `setupVisualNode` override.

// Before (18): inherited setupAnimationNode
const animationNode = ENGINE.AnimationStateMachineNode.create({

## 45. The root entry exports only public symbols; `./internal` is gone

`@gnsx/genesys.js` now lists the symbols a game uses (about 1,650 names). Debug helpers, editor plumbing and other names games do not use are no longer exported from the root, and the package no longer publishes `@gnsx/genesys.js/internal`. A few debug-only members of public classes were also hidden, so the types only they named left the root too. There is no deprecated shim and no replacement entry point.

```ts
// Before (18)
import { SomeEditorHelper } from '@gnsx/genesys.js/internal';
// After (19)
// Import only what the root exports. If a build error names a missing export, find the public replacement
// in .engine/src (the index.ts files list every public export); do not deep-import engine files.
import * as ENGINE from '@gnsx/genesys.js';
```

Games and templates that imported only from the root are unaffected, apart from the removals listed in §3.

## 46. `onBeginPlay` fires after the whole `beginPlay` override chain

Before, `onBeginPlay` ran inside `SceneNode.beginPlay`, before subclass overrides finished their own setup. Now the outermost `beginPlay` call fires it after every override has returned, on every path (world begin play, nodes added during play, direct calls). Code in `onBeginPlay` now sees what the subclass built: `PrimitiveNode` creates its physics body after `super.beginPlay()`, so `setPhysics*Param` calls in `onBeginPlay` find the body.

```ts
// Before (18): onBeginPlay ran before the physics body existed, so a workaround was needed
// After (19): the body exists in onBeginPlay
protected override onBeginPlay(): void {
  this.setPhysicsAngularDamping(0.2);
}
```

Remove workarounds that deferred physics setup to a later tick. Code that relied on `onBeginPlay` running before an override's own setup must move that work into the override, before `super.beginPlay()`.

## 47. `forwardDirection` and `rightDirection` default to world space

`SceneNode.forwardDirection(worldSpace = true)` and `rightDirection(worldSpace = true)` used the local quaternion, so a child of a turned node pointed the wrong way. They now use world space by default. Root nodes are unchanged. For the parent-space axis, pass `false`.

```ts
// Before (18): local axis, even for a child of a rotated parent
const dir = child.forwardDirection();
// After (19): world axis. Keep the old result with the parent-space flag
const dir = child.forwardDirection(false);
```

## 48. WebGPU draws with the meshlet pipeline by default

On WebGPU, games and the editor viewport now use the meshlet drawing pipeline fed from a scene registry (`DefaultDrawingPipelineType` is `'meshlet'`, `DefaultSceneRegistry` is `true`). The WebGL backend still draws with `standard`. Normal materials and nodes need no change. Check custom materials, custom shaders and code that walks `scene.children` for per-object draw state, because the registry draws registered objects, not the scene walk.

To keep 18's pipeline, set Drawing Pipeline to `standard` in Project Settings (saved as `drawingPipeline` in `.genesys-project`), or in code:

```ts
// Before (18): always the standard pipeline
// After (19): pick one by name to opt out
const renderer = await ENGINE.GenesysWebGPURenderer.create({ drawingPipeline: 'standard' });
```

Project Settings also has a Lighting choice (`lightingType`: standard, dynamic, clustered). The new viewport debug views (Geometry, Meshlet Clusters, Meshlet Batches, Drawing Pipeline) and the `drawingpaths` console command show which path draws each object and why.
